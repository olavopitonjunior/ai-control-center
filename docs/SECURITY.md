# SECURITY — AI Control Center

This project touches sensitive material: AI usage, provider credentials (indirectly),
project names, file paths, and process info. Security rules below are enforced in code
where noted and are non-negotiable (master spec §26).

## Credential boundary

1. **Provider credentials never leave the monitored machine.** The Surface receives only
   normalized _results_ (usage numbers, limits, costs), never keys/tokens/cookies.
2. When the OFFICIAL-quota integration lands, codexbar authenticates locally on the
   monitored machine; the agent reads its normalized JSON, not its secrets.
3. **No secrets in logs.** The agent's Fastify logger redacts `authorization` and
   `cookie` headers (`apps/agent/src/server.ts`, `redact:` config). We never log API
   keys, bearer/OAuth tokens, cookies, or session keys.
4. **No silent cookie extraction.** Any future browser-cookie access must be explicit,
   opt-in, and documented. Not present in M0/M1.

## Network exposure — enforced defaults

- The agent **binds `127.0.0.1` by default** (`ACC_AGENT_HOST`). Verified in M0: startup
  log reads _"loopback only (not reachable from the LAN)"_.
- Underlying tools stay local too: Glances is launched bound to `127.0.0.1` (its own
  default is `0.0.0.0` — we override it), and it is **never exposed directly**; only the
  agent faces the LAN.
- **Fail-closed:** `loadConfig()` throws if a non-loopback host is requested **without**
  `ACC_AGENT_TOKEN`. It is impossible to start LAN-exposed without a token.
- LAN access requires a **bearer pairing token** on `/v1/*`. Comparison is
  **constant-time** (`node:crypto.timingSafeEqual`) to avoid timing leaks. `/health` is
  public liveness only (no sensitive data).

## Pairing tokens

- High-entropy tokens (generated by the install scripts; ≥256-bit, base64url).
- Stored on the monitored machine and entered once on the Surface during pairing.
- Token files are `.gitignore`d (`agent-credentials.json`, `pairing-token.txt`).

## Transport security

- **Default:** plaintext HTTP on a **trusted private LAN only**, bearer-authenticated,
  loopback-by-default. Limitation: on a hostile LAN the bearer token and payloads are
  visible to a network attacker — documented, not hidden.
- **Optional TLS (M4, implemented):** set `ACC_TLS_CERT` + `ACC_TLS_KEY` and the agent
  serves **HTTPS** (verified). Generate a self-signed cert with `scripts/generate-cert.sh`;
  on the Surface, register the machine with an `https://` address. Self-signed certs aren't
  trusted by default — trust/pin the cert, or use a CA-signed cert for production. Transport
  is swappable without touching the protocol. Mutual-auth / cert-pinning-at-pairing is a
  future hardening step.

## Discovery (mDNS)

- Agents advertise `_ai-control._tcp` **only when LAN-exposed** (never on loopback). TXT
  records carry identity (machineId, os, hostname, version, scheme, auth-mode) — **never a
  token**. Discovery via `GET /v1/discover` is bearer-protected like the rest of `/v1/*`.

## Windows firewall

Install scripts add a firewall rule **only for the Private network profile**, and only
when the user explicitly enables remote monitoring. Never for Public.

## Diagnostics

Redacted by default. Any diagnostic bundle must be scrubbed of tokens, addresses on
request, and any credential-adjacent field before it can be shared.

## Data-at-rest

The Surface SQLite DB holds usage/history/project names/paths — treated as sensitive.
It is `.gitignore`d, stored in the app's local data dir, and never synced to any cloud
(see `PRIVACY` in README/§59). Exports must never include secrets.
